# Physische iPhone-Abnahme · OFFEN

Es wurde kein echtes iPhone, Safari oder VoiceOver eingesetzt. Chromium mit390×844 ist keine Geräteabnahme. Auch die ausstehenden Geräte-Gates aus UIUX1–5 bleiben offen.

## Designstudie

ZIP vollständig auf einen für den Tester zugänglichen lokalen statischen Server legen oder nach gesonderter Freigabe auf eine isolierte Test-Origin. **Dieser Auftrag veröffentlicht nichts.** iPhone Safari muss die echte HTML-Galerie laden; ein PNG oder ZIP-Preview ist kein Interaktionstest. Keine privaten Tagebuchdaten verwenden.

1. Safari hoch/quer, Browserleiste ein-/ausgeblendet: Heute und nächster Schritt, vier Ziele, Safe Areas, unterste Aktionen.
2. Reader beide Übersetzungen, Psalm119 bis176: scrollen, Vers auswählen, Farbe, Notiz, Fokusmodus verlassen. Bei200% Text und Displayzoom keine verlorenen Aktionen.
3. Journal langer Gedanke: Tastatur öffnen, Cursor ans Ende, Titel/Verknüpfung bearbeiten, Festhalten/Zurück erreichen. Apphintergrund und Rückkehr; Neuladen der Studie löscht absichtlich RAM-Demodaten und ist klar zu unterscheiden von der echten App.
4. Originaleintrag bearbeiten → alten Rückblick öffnen → damaliger Wortlaut und Datum bleiben; neuen Gedanken freiwillig ergänzen.
5. Quiz falsche/richtige Antwort, Referenz, Erklärung, später fortsetzen innerhalb derselben Sitzung. VoiceOver muss Frage, vier Optionen, Auswahl und Erklärung sinnvoll ansagen.
6. VoiceOver-Rotor: Überschriften, Buttons, Formulare; native Dialoge schließen und zum Auslöser zurückkehren. Externe Tastatur sofern vorhanden.
7. Vier Themes bei Tageslicht und niedriger Helligkeit, Markierungsfarben und dünne Baum-/Schwertlinien. Reduced Motion aktivieren.
8. Demo-JSON in Dateien exportieren, erneut auswählen, Vorschaubestand prüfen, Bestätigung abbrechen, anschließend bewusst wiederherstellen. Keine echten Backups verwenden.

## Spätere echte PWA (erst nach6B)

Die Designstudie ist absichtlich keine installierbare PWA. Deshalb können die folgenden Punkte hier nicht als bestanden gelten: Installation zum Home-Bildschirm, Standalone-Safe-Area, Offline-Kaltstart, Session-/Draftpersistenz nach Betriebssystembeendigung, Service-Worker-Update, echte Erinnerungsauslieferung. Für die echte App nach Integration auf derselben isolierten Origin Altversion mit synthetischen persönlichen Daten installieren → offline prüfen → Neuversion bereitstellen → Update durchführen → IDs, Entwürfe, Originalsnapshots, Backup und Markierungen vergleichen. Keinen Produktionsnutzerbestand als Testfixture verwenden.
