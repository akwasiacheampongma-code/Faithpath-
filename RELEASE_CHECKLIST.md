# Candidate, device gate and rollback

Phase7 is a maintenance candidate, not production authorization.

## Before a candidate is accepted

- [ ] Record actual branch/clean source HEAD, immutable baseline and unique BUILD.
- [ ] `npm ci`, both content master validators, all unit/regression tests pass.
- [ ] Lint, ESM graph and protected content/data contract checks pass.
- [ ] Build twice from the same frozen source and compare all emitted file bytes.
- [ ] Check all132 canonical Bible files, complete worker asset list and receipts.
- [ ] Run original browser flows/axe and responsive deep-link navigation.
- [ ] Exercise reader/quiz/path/journal/review/tree and backup restore/cancellation.
- [ ] Inject denied/quota/corrupt storage and late requests; retain exact data.
- [ ] Install immutable old app, reject a missing-asset update, reload old offline,
  then deliberately activate complete candidate on the **same isolated origin**.
- [ ] Verify draft, migration/safety keys, personal history and foreign cache.
- [ ] Inspect actual before/after screenshots. Maintenance must not redesign UI.
- [ ] Independent review complete; no unresolved mandatory-check failure.
- [ ] Archive logs, source/build/content hashes, source/delivery SHAs and ZIP hash.

## Physical iPhone / Safari / VoiceOver — OPEN until actually performed

Use a separately authorized isolated QA origin, never overwrite an existing QA
site as part of this task. Back up synthetic test data to Files first.

1. In iPhone Safari and an installed PWA, check320/390-width equivalents, all four
   themes, portrait/landscape, 150/200% text, safe areas and keyboard scroll.
2. Navigate Today/Bible/My Path/Journal/Discover/More and deep links; VoiceOver
   headings, landmarks, forms, error messages, focus and modal close/return.
3. Read long/short chapters in both translations, mark a verse, save a note,
   link it to a path, answer correct/incorrect quiz options and return later.
4. Create/edit/archive/restore a path; save/reopen a draft, add a historical
   review, verify original snapshot and unchanged tree count for ordinary tasks.
5. Export to Files; read-only check, explicit restore and restore Undo with a
   separate synthetic profile. Invalid file/cancel must not replace data.
6. Install old/new complete candidates on that same authorized QA origin. While
   an editor is open, preserve its draft. Deliberately update, restart the PWA,
   enable airplane mode and reload both translations and personal views.
7. Record iOS/device/Safari versions, installed/standalone mode, exact BUILD,
   expected/actual result, screenshots and any failure. Chromium is not this gate.

## Rollback without destructive data changes

Keep TREEFINAL source and complete artifact (`5390ec0a...`) plus candidate receipts.
Before any separately approved release, export synthetic and then real user data
through their owners. A later approved rollback must rebuild the compatible old
source under a **new unique rollback BUILD**, test it on the same isolated origin
and preserve Schema V5/keys. Reusing an old cache name or overwriting a live cache
with different bytes is unsafe. Do not clear LocalStorage/caches as a repair.

A failed installation should retain the old active complete worker. If the device
has lost its entire browser storage, only the owner's external backup can restore
entries. Reverting Git does not recover evicted personal data. No merge or publish
is included in the maintenance commands or CI.

## First-seed UX gate

- [ ] Confirm exact application commit, build receipt, unchanged content hash and
  byte-identical repeated build; distinguish later evidence-only commits.
- [ ] Recheck draft interruption/other editor/corrupt raw/quota/explicit discard,
  delayed final save, rapid tapping and navigation. No falsely saved late text.
- [ ] Actual backup restore includes the new path, prayer, reflection, verse and
  step with unchanged IDs; planting leaves development count unchanged.
- [ ] All seven art states, real branch targets, four themes,320/375/390/430/tablet,
 200% text, touch hit tests and finite/reduced/hidden motion checked.
- [ ] Hosted WebKit offline result resolved or explicitly blocks release; do not
  equate WebKit on Linux or Chromium zoom with physical iPhone Safari.
- [ ] UX-01/02/04 goals8of10 and UX-05 mean4of5 validated by ten actual people.
- [ ] Real iPhone Safari, installed PWA, VoiceOver and energy behavior recorded.
- [ ] No automatic release: merge/deployment needs separate user authorization.
